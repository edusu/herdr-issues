# Herdr Issues

A side panel beside Files and Changes that lists the GitHub issues of the repository the focused terminal is in, with the issue numbers that terminal mentions at the top, and a GitHub-style dialog to read an issue, comment, edit its labels, assign yourself, close and reopen it.

![Herdr Issues](preview.png)

## What you see

- **The Issues button**, at the right end of the tab bar after Files and Changes: a 26px pill with a circle-dot icon and "Issues", `selected` while its panel shows, `chrome` otherwise, like the tab bar's own panel buttons.
- **The panel**, in the side panel column (368px by default) as a card: 10px radius, 1px `border`, `background`.
  - A 42px header: a green (`ansi2`) circle-dot icon, "Issues" semibold, the repository (`owner/name`, 11px, `dim`, truncated, right-aligned) and a bordered "Refresh" button with a round arrow icon, or a spinner and "Syncing".
  - A filter area: a text field ("Filter issues") with a sort button ("Newest ▼"); below it two segmented controls, "Open 177 | Closed 100" on the left and "All | Mine" on the right.
  - The list: rows of `#number` (40px wide, `dim`) and the title (wrapping). When the focused terminal mentions issues, an "In this terminal" heading comes first with those rows (closed ones with a purple `ansi5` number), then a heading for the list below.
  - Before any repository has been seen: a centered circle-dot icon, "No repository yet" and "Focus a terminal inside a GitHub repository and its issues show up here."
- **The issue dialog**, 86% by 90% of the window, drawn after github.com's issue page:
  - A top bar: the repository, a Back button after following a link, an error if the last action failed, a spinner while refreshing or saving, and Refresh, Copy, Send to agent (greyed with a hover hint when the followed terminal has no agent), Start agent (greyed with a hint for a remote repository or when no folder is known), Open on GitHub and close buttons.
  - The title at 30px, regular weight, wrapping word by word with a `muted` `#number` after its last word. Below it a 32px state pill in GitHub's fixed colors (white on `#238636` Open, `#8957e5` Closed or Merged, `#6e7681` not planned) and an outlined pill per linked pull request.
  - Left, the timeline: full-width cards (6px radius, `border`) with a 38px `raised` header holding a 20px GitHub avatar, the login, "opened on Sep 26" or "29d ago", and pills for bot, Author and the GitHub role (Owner, Member, Contributor). Below the markdown, reaction pills (emoji and count). Events sit between the cards on a 2px line 20px in: a 28px round icon (tag, person, pencil, signpost, link, commit; filled purple for closed, green for reopened, grey for not planned), a 16px avatar, the bold login and what happened ("added Bug label", "closed this as completed", "mentioned this" with the referencing issue or pull request below, "added a commit that references this issue" with its short SHA). Then "Add a comment": a card with Write and Preview tabs, a textarea growing from 4 to 14 rows, "Close issue" (with a ▾ for completed or not planned) or "Reopen issue", and a green "Comment" button. Close asks first: the click swaps the close buttons for the reason ("Close as completed" or "Close as not planned", plus "with comment" when the box has text), Confirm and Cancel.
  - Right, a 264px sidebar of sections split by lines: Assignees ("No one · Assign yourself"), Labels (GitHub-style chips, with Edit), Milestone, Development (the linked pull requests) and Participants (avatars).
- **The copy menu**, a 300 by 222 popup: Copy link, Copy reference (`owner/repo#27`), Copy number (`#27`) and Copy number and title, each with the text it copies below it. Opened by right-clicking a row, it is 272 tall and ends with Send to agent and the agent's name below (dimmed, "No agent in the focused terminal", when there is none).
- **The start dialog**, a modal 560 by 540 dialog over the issue: "Start agent", a line saying a new branch from the default branch is made in its own worktree, a "Branch" input (default `issue-<n>-<slug of the title>`) with the worktree's folder or the branch error below it, "Open with" as buttons for Terminal and each installed agent (the first installed agent selected when the list arrives), the message in a textarea (4 to 8 rows, dimmed and labelled as unsent while Terminal is selected), an error line, and Cancel and a green Start.
- **The send dialog**, a modal 560 by 420 dialog over the issue: "Send to agent", "To <agent> · nothing is sent until you press Send", a textarea (8 to 14 rows) holding the message, an error line, and Cancel and a green Send.
- **The sort menu**, a popup: "Sort by" and Newest, Oldest, Recently updated, Least recently updated, Most commented, with a check on the current one.

## How it behaves

- The panel follows the focused terminal's folder (`panes()[i].cwd`), resolved to a repository with `gh repo view`. Each space remembers the repository its terminals were last in (across restarts): a folder outside any GitHub repository keeps it, and a space that never had one shows the empty state, never another space's repository.
- A repository's issues show at once from the cache. The first time, and every 6 hours, the panel fetches all open issues (up to 300) and the 100 most recently closed, in full. Every 30 seconds in between it fetches only issues updated since the last sync (`--search updated:>=…`, two minutes of overlap), in either state, and merges them. Refresh syncs now.
- While the panel isn't the shown side panel, it doesn't sync or read terminals; showing it syncs at once.
- Every 10 seconds it reads the focused terminal (`hc read --lines 100`) for `#123` and links to the repository's issues or pull requests, newest line first and each line left to right, up to 8. A terminal and text identical to the last scan aren't parsed again. Numbers that aren't open issues are looked up once (`gh issue view`) and remembered, including ones that don't exist, at most one per scan. A remote terminal (addressed `machine/t1`) isn't read: doing that every few seconds made typing in it lag.
- `settings.mentions` in `mod.json` (default `true`, editable in Better Config) turns that off: no timer runs, no terminal is read and "In this terminal" never shows. It is read once when the mod loads; saving `mod.json` reloads the mod. `settings.worktrees_root` (default `~/.herdr/worktrees`, a leading `~` is the home folder) is where Start agent puts worktrees; it is read from the same file and handed to the dialog when it opens.
- Filtering matches `#number` and title. Mine keeps issues assigned to the `gh` user. The counts on Open and Closed are of the cache.
- Clicking a row opens the dialog with the cached issue, which shows at once and refreshes behind it.
- In the dialog, `#123` and `owner/repo#123` outside code are links: issue and pull request links open in the dialog, with Back; other links open in the browser.
- Opening an issue loads it in full (`gh issue view` with milestone, linked pull requests and reactions) and its timeline (`gh api --paginate --slurp repos/…/issues/N/timeline`); label changes by one person within a minute are one line, and project and subscription events are left out. Avatars are downloaded once (`curl` from the timeline's `avatar_url` when it is a GitHub host, else `github.com/<login>.png`; https only, up to 1 MB) into `data/issues/avatars/`; bots without one get an initial.
- Images in a body or comment (`![alt](url)`, `<img src width>`, outside code) are cut out of the markdown, which draws none, and drawn between its runs: downloaded once into `data/issues/images/` (https only, `curl --max-filesize` 10 MB), measured from the file's header (PNG, JPEG, GIF, WebP, SVG), at their width attribute or own width but never wider than the thread column. github.com URLs (private repositories' attachments) go with the `gh` token, piped to `curl -H @-` and dropped by curl on the redirect to GitHub's storage host. Only images on `github.com` or `*.githubusercontent.com` over https download by themselves; any other shows "Load image from <host>" and downloads after a click, for that image and until the mod reloads (nothing is saved). Clicking a loaded one opens the file.
- Copy (in the issue's top bar, or right-clicking a row in the panel) opens the copy menu; picking a line writes it to the clipboard (`cx.write_to_clipboard`) and shows a "Copied" toast.
- Send to agent (the dialog's top bar, or the row's right-click menu) opens the send dialog with a message of three lines: `Please work on owner/repo#N: <title>`, the issue URL, and `Read it with: gh issue view N -R owner/repo --comments`. The title has newlines, control characters and runs of spaces collapsed to one space, quotes stay; the body is never included, because it is untrusted and can be long. The target is the agent of the terminal the panel follows, found among `agents()` by address; with none, the button and the menu entry are disabled. Send runs `hc send <address> <message>` (a message starting with `-` gets a leading space so `hc` reads it as text), after checking again that the terminal still has an agent, and keeps the dialog and the text with the error shown when `hc` fails (a blocked agent, say); on success it shows a "Sent" toast and closes. Ctrl+Enter sends too. Cancel and Esc close it and send nothing; a click outside doesn't close it.
- Start agent (the dialog's top bar only; disabled when the repository is on a remote machine or the panel has no folder) opens the start dialog with the same message. The folder is the one the panel follows (`where().cwd`), not necessarily the repository's root. Branch is checked as you type: letters, digits, `.`, `-`, `_` and `/`, and not what git refuses in them (a leading `-` or `/`, a trailing `/`, `.` or `.lock`, `..`, `//`, a part starting with `.`); the default is `issue-<n>-<slug>` with the title in lowercase ASCII (accents dropped, other characters and other scripts becoming one `-`), at most 50 characters in all, cut at a `-` when it can; a title with nothing ASCII gives `issue-<n>`. The worktree is `<root>/<owner>-<repo>/<branch with / as ->`, the layout Branch PR uses. Start runs, in the folder and each step stopping at the first failure with the program's message in the dialog: `gh repo view --json nameWithOwner,defaultBranchRef` (refused when the folder's repository is not the issue's), `git rev-parse --verify --quiet refs/heads/<branch>` (refused when the branch exists), a check that the path does not exist, `git fetch --no-tags -- origin <default>`, then `git worktree add -b <branch> -- <path> origin/<default>`. Nothing is forced or deleted. It then runs `space.new { folder: <path>, machine: "" }`; with an agent selected that also gets `argv` (the agent's `run`) and `task` (the message, trimmed, with a leading space if it starts with `-`; nothing when empty), so Herdr types the message once the agent is up. With Terminal selected, no message is sent. If the worktree exists but opening fails, the dialog keeps the error `Worktree created at <path>. Could not open it: …` and its button becomes Open, which retries only the opening. On success it shows a "Worktree opened" toast and closes. Ctrl+Enter in the message and Enter in the branch start too.
- Comment posts the box (also Ctrl+Enter); Preview renders it. Close and Reopen take the box's text along as a comment. Close (the button and both ▾ entries) only arms the confirmation row; Confirm runs `gh issue close`. Cancel, Back, a link to another issue, any other change and closing the dialog (Esc included) disarm it, so nothing is closed. Reopen, comment, labels and assignment stay one click. Edit lists the repository's labels with a check on the issue's; clicking one adds or removes it at once. Every change runs `gh issue …`, reloads the issue and tells the panel through shared state, which fetches that one issue so the list is current.
- The tab bar remembers each space's side panel only if it's in shared `workspace.panels`; the button adds `issues` there.

## Built from

- **Layout** (`layouts/main-issues.json`): Herdr's `main` 0.1.9. The `tabs` block sits in a 42px row `tab-bar` with a 78px block `issues-button` (`{ mod: "issues", props: { button: true } }`, `window_drag`). The `panel-body` stack gets a third child `issues` (`{ mod: "issues" }`).
- **Mod** `mods/issues/`: `main.js` is the panel, the button (props `button`), the sort menu (overlay props `sortMenu`) and the dialog (overlay props `issue: { repo, number, on, data, me, terminal }`), which `viewer.js` draws. `mod.json` carries the title, version and `settings` that Better Config edits, described by `mod.schema.json`. `icons.js` writes its Lucide icons to `data/issues/icons/` and downloads avatars to `data/issues/avatars/`; `pictures.js` splits markdown around its images and downloads and measures them; `pure.js` holds logic with no Herdr import (`opener`, the program that opens a link or file; `trusted`, whether an image URL is a GitHub host; `mentions`, the issue numbers in terminal text; `mentionsOn`, the `settings.mentions` switch; `closeLabel`, the text of the close confirmation; `brief`, the message sent to an agent; `sendArgs`, the arguments of `hc send`; `asText`, the leading-dash guard; `branchName` and `branchError`, the branch default and its check; `worktreesRoot`, the `settings.worktrees_root` setting; `worktreePath`, the worktree's folder), tested by `test/` with `node --test`. The copy menu is overlay props `copyMenu: { url, ref, number, title, send }` and the send dialog (`Sender`, in `viewer.js`) is overlay props `send: { terminal, message }`; the start dialog (`Starter`, which extends `Sender`) is overlay props `start: { repo, folder, root, number, title, message }`, and the issue dialog gets `folder` and `root` beside `terminal`; `send` is `null` in the copy menu when the caller doesn't offer sending.
- **herdr**: `spaces`, `panes`, `focused`, `layout`, `theme`, `exec`, `hc`, `run` (`layout.select`, `layout.show`, `layout.hide`, `space.new`), `knownAgents`, `home`, `openOverlay`, `closeOverlay`, `notify`, `agents`, `props`, `shared` / `setShared` (`issues.sort`, `issues.changed`, `workspace.panels`), `appHome`, `localStorage` (repositories per folder, the `gh` login, the last repository), `fs/promises` (the cache, and whether a worktree path exists), `readTextFile` (the mod's own `mod.json`, for `settings`).
- **gpui-base**: `TextView.markdown` with `on_link_click`, `TextareaState` / `Textarea`, `InputState` / `Input`.
- **Programs**: `open` (macOS), `xdg-open` (Linux) and `explorer.exe` (Windows) for links and images, `gh` (`repo view`, `api user`, `issue list`, `issue view`, `issue comment`, `issue close`, `issue reopen`, `issue edit`, `label list`, `api …/timeline`), `hc send`, `git` (`rev-parse`, `fetch`, `worktree add`), `curl` (avatars and images).

## Watch out

- Herdr doesn't draw SVGs or images from a symlinked mod folder (JavaScript loads fine), so icons and avatars live in the data folder and are drawn only once they're on disk; drawing a missing file first would leave it blank.
- The markdown view (`TextView.markdown`) draws no images at all, not even the alt text.
- `curl --max-filesize` only acts when the server announces the size, so a response without a length isn't capped; `--max-time` bounds it. An `http` image can't load even after the click: curl is limited to https.
- There's no inline styled text: the title is one element per word in a wrapping row, so the muted number can follow its last word.
- Saving a mod file reloads it; a dialog that was loading at that moment shows "interrupted". Reopen it.
- Herdr doesn't dock a symlinked mod from `mod.json`; `place` is `none` and the layout places it.
- `init`'s first argument isn't the overlay's props: read them with `props()`.
- The cache file holds full issues (bodies and comments) and is around 1 MB for 400 issues. A cache without `version: 2` starts with a full fetch.
- GitHub search can lag a few seconds behind a change, which the two minute overlap covers; the dialog's own changes don't wait for it.
- `hc send` types the text into the terminal and presses Enter, so it must only go to an agent: the dialog looks the terminal up in `agents()` again at Send. It matches `focused().terminal` to the agent's `address`; for a remote terminal (`machine/t1`) this is unverified, and with no match the button stays disabled.
- Start agent leaves the message to Herdr's `task` ("its first message" in `space.new`/`tab.new`) instead of polling for the agent to be ready; with no `argv` the message is dropped, so it can never reach a plain shell. How long Herdr waits for the agent, and what it does with a `task` starting with `-` or several lines, is unverified.
- `git fetch origin <default>` assumes the remote is called `origin` and is the repository `gh repo view` resolves; in a fork where `gh` resolves the upstream, the branch is cut from `origin`'s copy of that default name.
- The followed terminal is the last terminal that had focus (the panel itself has none), updated on every render and scan, not only when terminal reading is on.
- Pull requests open in the dialog read-only: no comment box, labels or state buttons.

## Done when

- `herdr-app check ~/.config/herdr-app/mods/issues` passes.
- An issue with an image on another host shows "Load image from <host>" and requests nothing until it is clicked; GitHub-hosted images load as before.
- Open on GitHub, a web link, a commit link and a clicked image open in the browser or the image's app on macOS, Linux and Windows.
- The tab bar shows Files, Changes and Issues; Issues opens and closes the panel, and switching spaces restores it.
- In a terminal inside a GitHub repository, the panel lists its open issues; Closed, Mine, the filter and each sort order change the list.
- `echo "#12"` in that terminal puts #12 under "In this terminal" within 10 seconds, and with `settings.mentions` set to `false` in `mod.json` the heading never shows and `hc read` is never called for the panel.
- A row opens the dialog at once; a `#number` link in the body opens that issue with Back.
- A comment, a label change, close and reopen show on github.com and in the panel's list.
- Close issue and both ▾ entries only show Confirm and Cancel; the issue stays open until Confirm. Cancel, Back and Esc leave it open.
- With a terminal running an agent focused before opening an issue, Send to agent (top bar, and right-click on a row) opens the message with the agent's name; editing it and pressing Send types it into that agent and shows a "Sent" toast; Cancel and Esc type nothing. With a plain shell followed, both entries are disabled.
- Start agent on an issue of a local repository opens a dialog with `issue-<n>-<slug>` as the branch and the installed agents beside Terminal. Start makes the branch and `<root>/<owner>-<repo>/<branch>` (`git worktree list` shows it, cut from the fresh `origin/<default>`), opens it as a new space and the chosen agent gets the message as its first prompt; Terminal opens a shell and sends nothing. An existing branch or folder shows an error and creates nothing; a repository on a remote machine has the button disabled with a hint. Changing `settings.worktrees_root` in `mod.json` moves new worktrees.
